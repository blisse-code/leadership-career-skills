# Leadership Case Study Canvas

Fill every section for flagship cases; supporting capsules can use sections 1-3, 6 (one decision), and 9.

---

## 1. Title
Formula: **[What changed] + [where/for whom] + [at what scale]**.
- Weak: "Telco App Redesign"
- Strong: "Unifying 3 country apps into one design system while rebuilding the team that owns it"

## 2. Signal strip (one line each)
```
Role: Head of Experience Design (led 12: 8 designers, 2 researchers, 2 content)
Partners: CPO, VP Engineering, 4 product managers
Timeline: 18 months (2023-2024)
Scale: 3 markets, ~9M customers [Need Human Review]
Outcome type: Platform + team build
Evidence tier: Medium (dashboards restricted; ranges shown)
```

## 3. 30-second skim (answer first, 5-8 lines max)
```
Mandate: [what was broken, who asked]
What I did: [the 2-3 leadership moves, not the process]
What changed: [outcome with baseline and timeframe; team/org outcome]
Hardest call: [the decision and its cost]
```
An executive who reads only this should know level, scope, judgment, and result.

## 4. The mandate and the tension
- Situation: context, market, product, org state (UX maturity level if useful).
- Complication: why it was hard (politics, legacy, time, money, capability gap).
- Stakes: what happens if unsolved, in business terms.
- Surface ask vs real problem: how the user reframed it. Reframing is a top seniority signal.

## 5. My role, team, and credits
Responsibility map:
```
Owned: ...
Led through others: [area]: the team did [execution], I set [direction/standard]
Influenced: [area]: argued for X, decision by [role]
Did not do: ...
```
Team: roles, count, notable contributions (credit people by role or first name if cleared).

## 6. Key decisions (3-5 blocks)
Each block:
```
### Decision: [informative headline, e.g. "We shipped the system to one market first, not all three"]
Tension: ...
Options: A (...), B (...), C (...)
Who wanted what: PM wanted..., Eng wanted..., Sales wanted...
My call and why: ...
What it cost: ...
What happened: ...
```
Include at least one decision where the user was overruled or conceded, and what they did next.

## 7. How I led (up, across, down)
- **Up**: how exec buy-in, budget, or sponsorship was won; how decisions were framed for executives (options, risk, cost of delay).
- **Across**: shared vocabulary, shared metrics with product/eng, conflict resolved, rituals with partners.
- **Down**: hiring, team structure, critique culture, coaching, delegation model, quality gates.
Show 1-3 artifacts: decision record, ritual calendar, framework diagram, before/after org chart, critique template. Sketches and diagrams are fine; leaders are judged on thinking.

## 8. The messy middle
- What broke or went wrong.
- What was descoped or compromised, and why that was right (or wrong).
- What changed the user's mind.
Frame as navigation and judgment, not complaint.

## 9. Outcomes (four lenses, pick what's real)
| Lens | Metric / observable change | Baseline | Result | Timeframe | Attribution limits |
|---|---|---|---|---|---|
| Product / user | | | | | |
| Business | | | | | |
| Team / org | | | | | |
| Operating model | | | | | |
Add one counter-metric or trade-off ("support contacts rose for 6 weeks during migration"). Add a third-party voice if available (exec quote, client renewal, peer testimonial).

## 10. What I'd do differently, and the reusable pattern
- 1-3 honest lessons.
- The pattern the user now reuses (name it, when to apply it, when not to).

---

## Headline test
Write sections 3-10 as single informative headlines. Read only the headlines. If they tell the story (mandate, decisions, leadership, outcome, lesson), the structure works. If they read "Background / Research / Design / Results", rewrite.

## Length guide
- Web long form: 1,200-2,000 words for flagship, with visuals.
- Skim: under 80 words.
- Capsule: 150-250 words.
