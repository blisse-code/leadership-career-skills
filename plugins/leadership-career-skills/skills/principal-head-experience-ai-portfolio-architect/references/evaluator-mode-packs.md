# Evaluator Mode Packs

## Overview

Different reviewer archetypes evaluate portfolios through different lenses. Ensure the portfolio can be read through any mode without collapsing.

---

## Mode 1: Academic Studio (CIID, MIT, Harvard, UAL)

### What They Value

- Craft and attention to detail
- Experimentation and iteration
- Intellectual depth and critical inquiry
- Process transparency (show the thinking)
- Methods awareness and rigor
- Originality and creative problem-framing

### What They Try to Invalidate

| Attack vector | Evidence that blocks it |
|---------------|------------------------|
| "This is just execution, no thinking" | Methods inventory, iteration documentation, dead ends shown |
| "No intellectual grounding" | Influences/bibliography, theoretical connections |
| "Craft is superficial" | Microinteraction detail, systematic design decisions |
| "Process is hidden" | Sketches, explorations, synthesis artifacts |
| "No critical reflection" | Explicit limitations, what would be done differently |

### Required Portfolio Elements

- Intent statement (research question or thesis)
- Methods inventory with limitations
- Influences and bibliography (5-12 references)
- Studio artifacts (sketches, iterations, dead ends)
- Critical reflection in each case study

### Academic Appendix Template

```markdown
## Academic Appendix

### Research Intent
What I'm investigating as a designer: [thesis/question]

### Methods Inventory
| Method | When I use it | Limitations |
|--------|--------------|-------------|
| [Method 1] | [Context] | [Weakness] |

### Influences
| Reference | Relevance to my practice |
|-----------|-------------------------|
| [Author/Work] | [1-line connection] |

### Studio Artifacts
[Link to iteration documentation, sketches, dead ends]
```

## Mode 2: Consulting (McKinsey, BCG, Bain)

### What They Value

- Answer-first communication (Pyramid Principle)
- Structured argumentation (MECE)
- Executive-proof claims
- Clear value connection
- Quantified impact
- Hypothesis-driven approach

### What They Try to Invalidate

| Attack vector | Evidence that blocks it |
|---------------|------------------------|
| "Can't get to the point" | Answer-first summaries, SCQA framing |
| "Gaps in logic" | MECE coverage, explicit structure |
| "Unsubstantiated claims" | Metrics with methodology |
| "No business impact" | Value-driver tree, revenue/cost connection |
| "Fuzzy thinking" | Hypothesis + validation pattern |

### Required Portfolio Elements

- Answer-first summary for every section
- SCQA framing for case study openings
- Value-driver tree showing design → business connection
- Quantified outcomes with attribution
- Structured argumentation throughout

### SCQA Framework

```markdown
**Situation**: [Stable context everyone accepts]
**Complication**: [What changed or threatened]
**Question**: [The question this raises]
**Answer**: [Your response, stated upfront]
```

### MECE Coverage Check

For each case study, verify:
- [ ] All relevant dimensions covered
- [ ] No overlapping categories
- [ ] Exhaustive within scope defined
- [ ] Gaps explicitly acknowledged

## Mode 3: Frontier AI Safety (Anthropic, OpenAI, DeepMind)

### What They Value

- Simplicity and clarity
- Transparency about limitations
- Evaluation-first thinking
- Careful ACI (agent-computer interface) design
- Safety and alignment awareness
- Intellectual honesty about uncertainty

### What They Try to Invalidate

| Attack vector | Evidence that blocks it |
|---------------|------------------------|
| "No evaluation rigor" | Evaluation plans, failure libraries, red-team artifacts |
| "Hides limitations" | Explicit uncertainty, failure modes documented |
| "Overclaims AI capability" | Honest assessment, guardrails shown |
| "No safety thinking" | Risk taxonomy, mitigation documentation |
| "Complexity for its own sake" | Simplicity rationale, minimal viable approach |

### Required Portfolio Elements

- AI governance dossier with evaluation artifacts
- Transparency surfaces documented
- Failure modes and edge cases enumerated
- Human oversight mechanisms
- Rollback and incident response

### Frontier AI Appendix Template

```markdown
## Frontier AI Appendix

### Tool Interface Documentation
| Tool | Inputs | Outputs | Constraints |
|------|--------|---------|-------------|
| [Tool] | [What it takes] | [What it returns] | [Limits] |

### Transparency Surface
| What user sees | What is hidden | Why hidden |
|----------------|----------------|------------|
| [Visible] | [Hidden] | [Rationale] |

### Evaluation-First Summary
- What was evaluated: [Methods]
- What failed: [Failures found]
- What guardrails changed: [Iterations]
```

## Mode 4: Systems and Operational (Palantir, Tesla, NVIDIA)

### What They Value

- Edge case handling
- Operational constraints awareness
- Failure handling and recovery
- Rigorous tradeoff analysis
- Systems thinking at scale
- Independent thinking and genuine curiosity

### What They Try to Invalidate

| Attack vector | Evidence that blocks it |
|---------------|------------------------|
| "Didn't think about edge cases" | Edge-case library (8+ per study) |
| "No operational awareness" | Failure handling narrative |
| "Shallow tradeoffs" | Multi-dimensional tradeoff analysis |
| "Can't handle complexity" | Systems dependencies documented |
| "Lacks intellectual curiosity" | Novel questions, independent investigation |

### Required Portfolio Elements

- Edge-case library per flagship study (minimum 8)
- Failure handling narrative
- Human escalation paths
- Operational cost considerations
- Systems dependency maps

### Question Strategy Pack

Prepare 6-10 questions per target company that demonstrate:
- Independent thinking
- Genuine curiosity about their problems
- Understanding of their domain constraints
- Non-standard, thoughtful inquiry

**Filter**: No standard interview questions. Teams like Palantir explicitly dislike canned questions.

## Mode 5: Consumer-Scale UX (Google, Apple, Meta)

### What They Value

- Clarity and accessibility
- Purposeful motion and interaction
- Scalable interaction patterns
- User-centered evidence
- Systematic design decisions
- Attention to craft at scale

### What They Try to Invalidate

| Attack vector | Evidence that blocks it |
|---------------|------------------------|
| "Doesn't scale" | Pattern reusability, systematic approach |
| "Motion is decoration" | Motion purpose documented |
| "Accessibility afterthought" | Accessibility-first decisions |
| "No user evidence" | Research methodology, user validation |
| "Inconsistent craft" | Design system thinking, token discipline |

### Required Portfolio Elements

- Microinteraction proof bundles
- Accessibility documentation
- Systematic design decisions
- User research methodology
- Scalability considerations

## 30-Minute Portfolio Review Deck Mode

For timed portfolio reviews, output:

### Presentation Outline (30 min for 1-2 projects)

| Minute | Content | Notes |
|--------|---------|-------|
| 0-2 | Introduction, role, positioning | Signal strip |
| 2-7 | Project 1: Context + Problem | SCQA framing |
| 7-15 | Project 1: Approach + Key decisions | Demo moments |
| 15-18 | Project 1: Outcomes + Lessons | Metrics + reflection |
| 18-23 | Project 2: Compressed narrative | If time allows |
| 23-28 | Q&A | Use trap list |
| 28-30 | Close + next steps | CTA |

### Q&A Trap List

Anticipate challenges and prepare responses:

| Likely question | Trap | Prepared response |
|-----------------|------|------------------|
| "What would you do differently?" | Admitting major failure without learning | [Balanced response] |
| "How do you know it worked?" | Overclaiming attribution | [Honest attribution] |
| "Why this approach?" | Can't articulate tradeoffs | [Explicit tradeoffs] |

### One-Slide-Per-Concept Discipline

Structure presentation so each concept survives interruption:
- Each slide = one complete thought
- No dependencies across slides for comprehension
- Can skip slides without losing thread
